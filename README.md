# VaultText — Max Secure PWA

Локальное PWA без сервера и внешних библиотек.

## Как работает

### Первичная настройка

1. Откройте приложение.
2. Нажмите «Создать секрет».
3. Приложение генерирует случайный 160-битный TOTP-секрет.
4. Скопируйте Base32-ключ.
5. В Google Authenticator добавьте аккаунт вручную:
   - ключ настройки = этот Base32;
   - тип = Time based.
6. Введите текущий 6-значный код.
7. После проверки секрет остаётся в браузере как **non-extractable HMAC CryptoKey** в IndexedDB.

Секрет после создания нельзя экспортировать через Web Crypto API. Для резервного восстановления пользователь может самостоятельно сохранить показанный Base32-ключ; приложение само его наружу не отправляет.

## Шифрование

Каждое сообщение получает новую случайную 256-битную соль. Постоянный TOTP-секрет через HMAC + HKDF превращается в отдельный AES-256-GCM ключ для этого сообщения. Текст шифруется с уникальным 96-битным nonce.

Шифр-код:

`VT2.<header-base64>.<ciphertext-base64>`

В header находятся версия, алгоритмы, соль и nonce. TOTP-секрет в него не попадает.

## Расшифровка

Для расшифровки нужны одновременно:

1. полный VT2-шifр-код;
2. локальный TOTP-секрет этого экземпляра приложения;
3. актуальный 6-значный TOTP-код.

Сам шифр-код без локального секрета не раскрывает текст.

## Почему старые сообщения продолжают работать

TOTP меняется каждые 30 секунд, поэтому текущая цифра не используется как постоянный ключ. Она используется как доказательство владения TOTP-секретом. Криптографический ключ сообщения получается из постоянного секрета + уникальной соли сообщения.

Для небольшого дрейфа часов принимаются текущий, предыдущий и следующий 30-секундные интервалы.

## Хранение

- исходный текст не сохраняется;
- TOTP-код не сохраняется;
- сервер отсутствует;
- сеть не нужна после кэширования PWA;
- сторонних CDN и JS-библиотек нет;
- TOTP-секрет хранится в IndexedDB как non-extractable CryptoKey.

### Ограничение браузера

Web Crypto не гарантирует универсальную аппаратную привязку ключа к Secure Enclave/TPM на всех браузерах. Поэтому нельзя честно обещать абсолютную защиту от вредоносного ПО, полного контроля браузерного профиля или компрометации ОС.

Для особо критичных секретов нужен независимый криптографический аудит и аппаратный фактор, например WebAuthn/passkey или аппаратный ключ.

## GitHub Pages

1. Создайте репозиторий.
2. Распакуйте содержимое ZIP в корень.
3. GitHub → Settings → Pages.
4. Source: Deploy from a branch.
5. Branch: `main`, folder `/ (root)`.
6. Откройте HTTPS-адрес GitHub Pages.

## Важное замечание

Приложение намеренно не использует онлайн-сервис генерации QR-кодов: иначе TOTP-секрет пришлось бы передавать третьему сайту. Вместо этого используется локальная ручная регистрация по Base32 setup key. Это лучше соответствует требованию «никаких данных за пределы устройства».

Проект не является сертифицированным криптографическим продуктом.
